# AGENTS.md

## Projekt

Dette projekt er en hjemmeside til det fiktive event "Vores Lagersalg" i København.

Projektet bruges som en øvelse i webudvikling samt Git og GitHub. Koden skal derfor være enkel, overskuelig og nem at videreudvikle.

## Teknologi

Projektet skal udvikles med:

- HTML
- CSS

Brug ikke:

- frameworks
- backend
- eksterne pakker
- unødvendig JavaScript

Hvis JavaScript ikke er nødvendigt for funktionaliteten, skal det ikke tilføjes.

## Projektstruktur

Hold projektstrukturen enkel og overskuelig.

Som udgangspunkt skal projektet indeholde:

- `index.html`
- en separat CSS-fil
- `assets/` til eventuelle billeder og andre ressourcer
- `AGENTS.md`

Placér billeder i en relevant mappe under `assets`.

Undgå at oprette unødvendige filer eller mapper.

## HTML

Brug semantisk HTML, hvor det giver mening.

Koden skal:

- være let at læse
- have en logisk struktur
- bruge passende HTML-elementer
- undgå unødvendige wrappers
- have meningsfulde class-navne

Siden skal kunne forstås og vedligeholdes af en studerende.

## CSS

CSS skal placeres i en separat fil.

Hold styling:

- overskuelig
- organiseret
- responsiv
- så enkel som muligt

Undgå unødvendigt komplicerede selectors og gentagelser.

Brug CSS Grid og Flexbox, hvor det er relevant.

## Responsivitet

Hjemmesiden skal fungere på både desktop og mobil.

Sørg især for:

- at tekst ikke går uden for viewporten
- at store overskrifter skalerer korrekt
- at billeder er responsive
- at layouts tilpasses mindre skærme
- at navigation og links fortsat er brugbare på mobil

## Tilgængelighed

Brug grundlæggende god webtilgængelighed.

Det betyder blandt andet:

- relevante `alt`-tekster på billeder
- tydelige links
- tilstrækkelig kontrast mellem tekst og baggrund
- korrekt heading-hierarki
- semantiske HTML-elementer, hvor det er muligt

## Arbejde med eksisterende kode

Før du foretager ændringer:

1. Undersøg de eksisterende filer.
2. Forstå den nuværende struktur og styling.
3. Genbrug eksisterende løsninger, hvor det giver mening.
4. Foretag kun de ændringer, der er nødvendige for den aktuelle opgave.

Omskriv ikke fungerende dele af projektet uden grund.

## Ændringer

Når der bliver bedt om en ændring, skal ændringen være så fokuseret som muligt.

Undgå at:

- redesigne andre sektioner uden at blive bedt om det
- ændre eksisterende tekst uden grund
- ændre fungerende navigation
- tilføje nye funktioner, der ikke er efterspurgt
- refaktorere store dele af projektet ved små ændringer

Dette er særligt vigtigt, fordi projektet bruges til at arbejde med Git og GitHub, hvor ændringer skal være nemme at identificere i versionshistorikken.

## Git

Foretag ikke Git-handlinger på egen hånd.

Du må ikke:

- oprette commits
- pushe til GitHub
- ændre branches
- merge branches
- slette branches
- ændre Git-konfiguration

medmindre brugeren specifikt beder om det.

Fokuser på at ændre projektets filer. Brugeren styrer Git- og GitHub-processen.

## Generelt

Prioritér:

1. Fungerende kode
2. Overskuelig kode
3. Responsivt design
4. Konsistens med det eksisterende design
5. Små og kontrollerede ændringer

Hvis en eksisterende løsning allerede fungerer, skal den som udgangspunkt bevares.
